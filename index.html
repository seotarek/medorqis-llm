System Design

The Dual-Track Clinical Architecture

Separating linguistic comprehension from deterministic arithmetic to guarantee mathematical zero-error invariance.

01

The Flaw of Traditional Medical LLMs

Standard LLMs calculate complex formulas (such as CKD-EPI eGFR or Cockcroft-Gault CrCl) via next-token probability. This causes arithmetic drift and rounding hallucinations of 15% to 40%, which can lead to inappropriate drug dosing or missed kidney disease staging.

02

The MedOrqis Zero-Token Engine

Instead of computing math inside neuron weights, MedOrqis-LLM extracts clinical parameters and generates a native <tool_call> targeting 12 hardcoded deterministic algorithms. Result: 0.00% calculation error and strict guideline compliance.

03

Bilingual Dialect Normalization

Maps colloquial Egyptian, Saudi, and Levantine patient phrases (e.g., "نهجان وكتمة في صدري", "ضربات قلبي سريعة") into standard SNOMED-CT / ICD-10 clinical concepts before processing.

1. Why Base Model Fails

Without fine-tuning, autoregressive foundation models attempt arithmetic in text. On non-linear formulas (e.g. CKD-EPI or Schwartz), they hallucinate numbers that sound plausible but introduce fatal dosing errors.

2. Determinism Advantage

MedOrqis-LLM transforms the LLM into a parser and narrative reasoner. By offloading arithmetic to deterministic verified code, calculation error rate drops to absolute zero.

3. Overdose Protection

In pediatric cases where calculated weight dose exceeds adult single maximum (e.g., 45kg child @ 10mg/kg = 450mg), MedOrqis enforces the 400mg adult ceiling cap automatically.

Deployment

Production Quickstart

Deploy MedOrqis-LLM locally or in high-throughput cloud environments using standard Hugging Face or vLLM engines.

Python (Transformers + PEFT) Inference Template 
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

base_model_id = "Applied-Innovation-Center/Karnak-6B-v1.0"
lora_repo_id = "seotarek/medorqis-llm"

# 1. Load Tokenizer & 4-bit Base Model
tokenizer = AutoTokenizer.from_pretrained(lora_repo_id, trust_remote_code=True)
base_model = AutoModelForCausalLM.from_pretrained(
    base_model_id,
    load_in_4bit=True,
    device_map="auto",
    torch_dtype=torch.float16,
    trust_remote_code=True
)

# 2. Attach Fine-Tuned MedOrqis LoRA Adapters
model = PeftModel.from_pretrained(base_model, lora_repo_id)
model.eval()

# 3. Apply Native Chat Template
messages = [
    {"role": "system", "content": "You are MedOrqis Clinical AI. Always invoke deterministic tools for calculations."},
    {"role": "user", "content": "Evaluate CKD-EPI 2021 eGFR for a 54yo female with creatinine 1.4 mg/dL."}
]
prompt = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
inputs = tokenizer(prompt, return_tensors="pt").to("cuda")

# 4. Generate Clinical Recommendation
with torch.no_grad():
    outputs = model.generate(**inputs, max_new_tokens=256, do_sample=False)

print(tokenizer.decode(outputs[0][len(inputs['input_ids'][0]):], skip_special_tokens=True))
High-Throughput Production Serving (vLLM) CLI Serving 
vllm serve Applied-Innovation-Center/Karnak-6B-v1.0 \
    --enable-lora \
    --lora-modules medorqis-llm=seotarek/medorqis-llm \
    --max-model-len 4096 \
    --gpu-memory-utilization 0.90 \
    --dtype float16
Context Window Note: While the underlying tokenizer architecture supports extended context up to 131,072 tokens, --max-model-len 4096 is specifically recommended for high-concurrency production deployments on edge/commodity GPUs (NVIDIA Tesla T4 / L4) to minimize KV cache footprint.
